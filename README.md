# Three MLOps Teaching Labs: House-Value Prediction

A connected example using **real California Housing census data**,
Scikit-Learn, FastAPI, Docker, and Docker Compose.

**Scenario:** A property-research application requests an estimated median house
value for an area, based on income, house age, rooms, population, and location.
The data is from 1990 and describes census block groups, not individual homes.
This is a teaching example, not a current property appraisal.

## See the Real Training Data

It contains **16,512 training rows** with eight inputs and one known price.
[artifacts/test_data.csv](artifacts/test_data.csv) contains **4,128 unseen test rows**.
Both are generated by training; the target is `median_house_value_usd`.

First three training rows, with selected columns rounded for display:

| Area Median Income | Median House Age | Average Rooms | Known Median House Value |
| --- | --- | --- | --- |
| $32,596 | 33 years | 5.02 | $103,000 |
| $38,125 | 49 years | 4.47 | $382,100 |
| $41,563 | 4 years | 5.65 | $172,600 |

Other columns include bedrooms, population, occupancy, latitude, and longitude.
Income in the CSV uses $10,000 units: `3.2596` means $32,596. Prices are already
converted to dollars. The model learns from the input columns and known price;
at prediction time it receives only the inputs and estimates the missing price.

The dataset contains 20,640 real census-area records and is loaded with
Scikit-Learn's `fetch_california_housing()`.
[Dataset documentation](https://scikit-learn.org/stable/modules/generated/sklearn.datasets.fetch_california_housing.html).

## Step 1: Set Up Python

Prerequisites: Python 3.12 or 3.13 and internet for the first dataset download.
Run from this project folder. Scikit-Learn caches subsequent dataset loads.
The current workspace already has a configured `.venv`; creation and installation
below are also provided for students starting on a fresh machine.

```powershell
py -3.12 -m venv .venv
$Python = Join-Path (Get-Location) ".venv\Scripts\python.exe"
& $Python -m pip install -r requirements-dev.txt
```

Use the `.venv` interpreter in VS Code. These commands call it directly, so
PowerShell activation is not required. In a new terminal, set `$Python` again
or use `.\.venv\Scripts\python.exe` directly.

## Step 2: Train and Evaluate

```powershell
& $Python train.py
& $Python -m pytest -q
Get-Content artifacts\training_data.csv -TotalCount 6
Get-Content artifacts\metrics.json
Import-Csv artifacts\model_comparison.csv | Format-Table
Get-Content artifacts\prediction_examples.json
```

Training compares **three regression models** using the same training/test split
and three training-only validation folds. Each predicts a numeric value rather
than a category. The lowest cross-validation MAE determines which model is saved
as the serving artifact; test scores do not choose the winner.

| Model | How It Works | Training CV MAE | Test MAE |
| --- | --- | --- | --- |
| Linear Regression | Learns a weighted sum of the input features | $52,925 | $53,320 |
| Random Forest | Averages predictions from 50 trees trained on resampled data | $34,429 | $33,293 |
| Gradient Boosting | Builds trees sequentially to reduce prediction errors | **$31,972** | **$30,960** |

Gradient Boosting (`histgb`) is selected in this run. Lower MAE is better;
these results apply to this dataset, split, and configuration, not all problems.
The API serves **one selected model**, not an average of the three.

Open [artifacts/model_comparison.csv](artifacts/model_comparison.csv) for all scores.
All three fitted models are also saved in `artifacts/models` for classroom comparison:
[Linear Regression](artifacts/models/linear_regression.joblib),
[Random Forest](artifacts/models/random_forest.joblib), and
[Gradient Boosting](artifacts/models/histgb.joblib).
The selected model is copied to [artifacts/model.joblib](artifacts/model.joblib).
See the [Teaching Guide](TEACHING_GUIDE.md) for explanations and exercises.

## Step 3: Choose How to Serve

Use **either local Python or Docker** on port 8000, not both at once.
The current deployment uses Docker; skip the local option to keep it running.

### Option A: Local Python

If Docker is using port 8000, stop its API first with `docker compose stop model-api`.

```powershell
& .\.venv\Scripts\python.exe -m uvicorn api:app --host 127.0.0.1 --port 8000
```

Keep this terminal open. This option does **not** run inside Docker. Stop it
with Ctrl+C before switching to Option B.

Open http://127.0.0.1:8000/docs and expand `POST /predict`. Select **Try it out**
and use this published-dataset example:

```json
{
  "median_income": 8.3252,
  "house_age": 41.0,
  "average_rooms": 6.984126984126984,
  "average_bedrooms": 1.0238095238095237,
  "population": 322.0,
  "average_occupancy": 2.5555555555555554,
  "latitude": 37.88,
  "longitude": -122.23
}
```

In a second PowerShell terminal, verify the running service:

```powershell
& .\.venv\Scripts\python.exe smoke_test.py
```

### Option B: Docker Compose

Start Docker Desktop in Linux-container mode and wait until `docker info` succeeds.
Stop the local Uvicorn server first, or select a different port.

```powershell
docker compose config --quiet
docker compose up --build -d --wait model-api
docker compose --profile checks run --rm smoke-check
docker compose ps
```

If starting on a fresh machine, complete Steps 1 and 2 first. Required build
inputs are [artifacts/model.joblib](artifacts/model.joblib),
[artifacts/metadata.json](artifacts/metadata.json), and
[artifacts/metrics.json](artifacts/metrics.json).

Train locally first; the Docker build packages the resulting trusted model,
metadata, and metrics. The training/test CSVs remain on the host for teaching.
There is no dataset download or training inside the image build. A fresh build
still needs network access to pull the base image and install packages.
The optional smoke-check container waits for readiness and calls the API over
the Compose network. No database is required.

The `smoke-check` container waits for model readiness, calls `http://model-api:8000`
through Compose networking, and verifies a dollar prediction and input validation.
A successful run prints `PASS` and exits with status 0.

## Step 4: Send a Prediction Request

This works for either serving option. Run from a second PowerShell terminal:

```powershell
$body = Get-Content artifacts\sample_request.json -Raw
Invoke-RestMethod -Uri http://127.0.0.1:8000/predict -Method Post -ContentType "application/json" -Body $body
```

The sample contains inputs from the first held-out test row, whose known median
value is $47,700. The verified response is:

```json
{
  "predicted_median_house_value_usd": 58812.23,
  "model_version": "housing-histgb-v1",
  "notice": "Historical census-area estimate for teaching, not a current property appraisal."
}
```

The absolute error for this example is $11,112.23. The known price is used to
evaluate the estimate, not passed into the prediction request.

## Logs, Ports, and Shutdown

```powershell
docker compose logs --tail 50 model-api
docker compose ps
```

To use host port 8001 instead, set `$env:API_PORT = "8001"` before running
`docker compose up --build -d --wait model-api`. Browse
http://127.0.0.1:8001/docs; the container's internal port remains 8000.
Remove the override with `Remove-Item Env:API_PORT` when finished.

When you are finished with the Docker demonstration:

```powershell
docker compose down
```

## Troubleshooting

| Problem | Action |
| --- | --- |
| Old Docker build fails during `python train.py` with `CERTIFICATE_VERIFY_FAILED` | Use the updated Dockerfile: train locally, then package the artifacts. Do not disable TLS verification. |
| Docker COPY cannot find model files | Complete Step 2 before building. |
| Port 8000 is already in use | Stop the local API or choose host port 8001. |
| Docker Linux engine is unavailable | Start Docker Desktop in Linux-container mode and confirm `docker info` succeeds. |
| API returns 422 | Supply all eight numeric fields; use positive values for the first six and valid coordinates. Negative longitude is expected. |
| Prediction still uses an older model | Retrain locally, rebuild with Compose, and check `/model`. |

The original build-time training failed because the container could not verify
the dataset host's certificate chain. The corrected build deploys already-trained
artifacts; it does not disable certificate checks or modify the trust store.

## GitHub Continuous Integration

[.github/workflows/ci.yml](.github/workflows/ci.yml) defines the **ML Model CI**
pipeline. It runs automatically for pull requests targeting `main` and pushes
to `main`, and can also be started from GitHub's **Actions** tab with **Run workflow**.

| Check | What It Verifies |
| --- | --- |
| Python 3.12 tests | Installs pinned dependencies and runs the training/API workflow tests |
| Python 3.13 tests | Runs the same tests on the other supported local Python version |
| Docker model-serving check | Builds the image, waits for readiness, and runs the checker in another container |

The Python 3.12 job also runs training and uploads the selected model, metadata,
metrics, and comparison CSV as a temporary workflow artifact. The Docker job
downloads those files into `artifacts/` before building. This is necessary because
generated models are deliberately not committed to Git. The model is still trained
outside the Docker build, preserving the certificate-safe deployment workflow.

JUnit test reports and the serving artifact are downloadable from the workflow
run for seven days. The container job prints status and logs, then cleans up
containers even if a check fails. Each job has a 15-minute timeout.

CI uses read-only repository permissions and does not require custom secrets.
It does not publish an image or deploy to a cloud service. Initial package, base
image, and housing-data downloads still require network access on the runner.

For a pull request, open its **Checks** tab to inspect failures. The repository
owner can separately configure branch protection to require these checks before
merging; adding a workflow does not automatically enable branch protection.
